# 事务和隔离级别

事务用来保证一组 SQL 要么都成功，要么都失败。

最典型的例子是转账：

1. A 账户扣 100。
2. B 账户加 100。

这两步必须作为一个整体。不能只扣了 A，却没有给 B 加钱。

## 一、准备账户表

```sql
CREATE TABLE accounts (
    id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50) NOT NULL,
    balance DECIMAL(10, 2) NOT NULL DEFAULT 0.00,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

插入数据：

```sql
INSERT INTO accounts (username, balance)
VALUES
    ('alice', 1000.00),
    ('bob', 500.00);
```

## 二、开启事务

```sql
START TRANSACTION;
```

执行扣款：

```sql
UPDATE accounts
SET balance = balance - 100
WHERE username = 'alice';
```

执行加款：

```sql
UPDATE accounts
SET balance = balance + 100
WHERE username = 'bob';
```

确认无误后提交：

```sql
COMMIT;
```

提交后，修改才真正确认下来。

## 三、回滚事务

如果执行中发现问题，可以回滚：

```sql
START TRANSACTION;

UPDATE accounts
SET balance = balance - 100
WHERE username = 'alice';

-- 发现条件写错了，撤销本次事务
ROLLBACK;
```

`ROLLBACK` 会撤销当前事务里还没有提交的修改。

## 四、自动提交 autocommit

MySQL 默认通常是自动提交模式。

也就是执行一条：

```sql
UPDATE accounts
SET balance = balance + 10
WHERE id = 1;
```

它会自动提交。

查看自动提交状态：

```sql
SELECT @@autocommit;
```

结果为 `1` 表示开启自动提交。

显式执行：

```sql
START TRANSACTION;
```

后，后续 SQL 会进入事务，直到 `COMMIT` 或 `ROLLBACK`。

## 五、事务的 ACID

事务有四个重要特性：

| 特性 | 含义 |
|------|------|
| 原子性 Atomicity | 要么都成功，要么都失败 |
| 一致性 Consistency | 事务前后数据要满足约束和业务规则 |
| 隔离性 Isolation | 多个事务同时执行时互相隔离 |
| 持久性 Durability | 提交后的数据不会因为普通故障随便丢失 |

先重点理解“要么都成功，要么都失败”。

## 六、并发修改的问题

假设两个请求同时给同一篇文章浏览量加 1。

推荐写法：

```sql
UPDATE posts
SET view_count = view_count + 1
WHERE id = 1;
```

不要在应用层先查出来再自己加：

```text
查出 view_count = 10
应用里加 1 得到 11
写回 view_count = 11
```

并发时两个请求都可能读到 10，最后都写回 11，导致少加一次。

直接在 SQL 里写 `view_count = view_count + 1`，数据库会更好地处理并发更新。

## 七、SELECT ... FOR UPDATE

如果需要先查询再根据结果更新，可以在事务里加锁。

例如扣库存：

```sql
START TRANSACTION;

SELECT stock
FROM products
WHERE id = 1
FOR UPDATE;

UPDATE products
SET stock = stock - 1
WHERE id = 1 AND stock > 0;

COMMIT;
```

`FOR UPDATE` 会对查询到的行加排他锁，其他事务要修改这些行时需要等待。

注意：

- 必须在事务里使用才有意义。
- 查询条件应该尽量命中索引。
- 锁持有时间越短越好。

## 八、隔离级别

隔离级别决定多个事务同时执行时彼此能看到什么。

MySQL 常见隔离级别：

| 隔离级别 | 简单说明 |
|----------|----------|
| `READ UNCOMMITTED` | 可能读到别人还没提交的数据 |
| `READ COMMITTED` | 只能读到别人已经提交的数据 |
| `REPEATABLE READ` | 同一事务中多次普通读取结果尽量保持一致，MySQL InnoDB 默认常用级别 |
| `SERIALIZABLE` | 隔离最强，并发能力最低 |

查看当前隔离级别：

```sql
SELECT @@transaction_isolation;
```

设置当前会话隔离级别：

```sql
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
```

本地练习时不需要频繁修改隔离级别，但要知道它会影响并发读写行为。

## 九、事务只对支持事务的引擎有效

InnoDB 支持事务。

MyISAM 不支持事务。

所以业务表建议使用：

```sql
ENGINE=InnoDB
```

如果表不是 InnoDB，即使写了 `START TRANSACTION`，也不能得到完整事务能力。

## 十、事务使用原则

| 原则 | 说明 |
|------|------|
| 多步关键操作放事务 | 例如转账、下单、扣库存 |
| 事务越短越好 | 不要在事务里做慢接口调用 |
| 事务里尽量按固定顺序更新表 | 降低死锁概率 |
| 失败要回滚 | 后端代码捕获异常后执行回滚 |
| 使用 InnoDB | 业务表不要使用不支持事务的引擎 |

事务是数据库可靠性的核心能力，后面做项目时会经常用到。
