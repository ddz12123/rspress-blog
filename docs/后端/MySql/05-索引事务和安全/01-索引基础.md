# 索引基础

索引用来加速查询。

没有索引时，MySQL 可能需要从头到尾扫描整张表。数据少时感觉不明显，数据多了就会变慢。

## 一、索引可以怎么理解

可以把索引理解成书的目录。

如果没有目录，要找某个章节，只能一页一页翻。

有目录后，可以先定位章节，再跳到具体页面。

数据库索引也是类似思路：先通过索引快速定位数据，再读取对应行。

## 二、主键自带索引

创建主键：

```sql
id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT
```

MySQL 会自动为主键创建索引。

所以按主键查询通常很快：

```sql
SELECT id, username, email
FROM users
WHERE id = 1;
```

## 三、唯一约束也会创建唯一索引

```sql
email VARCHAR(100) NOT NULL UNIQUE
```

这会创建唯一索引，既能加速查询，也能防止重复邮箱。

查询邮箱：

```sql
SELECT id, username, email
FROM users
WHERE email = 'tom@example.com';
```

这类查询适合走邮箱索引。

## 四、普通索引

给文章状态创建索引：

```sql
CREATE INDEX idx_posts_status
ON posts (status);
```

查询：

```sql
SELECT id, title
FROM posts
WHERE status = 'published';
```

可能会使用 `idx_posts_status`。

## 五、联合索引

如果经常按用户、状态、时间查询文章：

```sql
SELECT id, title, created_at
FROM posts
WHERE user_id = 1 AND status = 'published'
ORDER BY created_at DESC;
```

可以创建联合索引：

```sql
CREATE INDEX idx_posts_user_status_created
ON posts (user_id, status, created_at);
```

联合索引的字段顺序很重要。

## 六、最左前缀原则

联合索引：

```sql
(user_id, status, created_at)
```

比较适合这些条件：

```sql
WHERE user_id = 1
```

```sql
WHERE user_id = 1 AND status = 'published'
```

```sql
WHERE user_id = 1 AND status = 'published'
ORDER BY created_at DESC
```

不太适合只按 `status` 查：

```sql
WHERE status = 'published'
```

因为它跳过了联合索引最左边的 `user_id`。

先记住一句话：联合索引通常要从最左边字段开始连续使用。

## 七、LIKE 和索引

可以较好利用索引：

```sql
WHERE title LIKE 'MySQL%'
```

很难利用普通 B-Tree 索引做快速定位：

```sql
WHERE title LIKE '%MySQL%'
```

原因是 `%MySQL%` 前面有通配符，数据库不能从索引开头定位。

如果需要做大量全文搜索，可以了解 MySQL 全文索引或专门的搜索引擎。当前阶段先知道普通 `LIKE '%关键字%'` 数据多了可能慢。

## 八、查看执行计划 EXPLAIN

用 `EXPLAIN` 查看 SQL 可能怎么执行：

```sql
EXPLAIN
SELECT id, title
FROM posts
WHERE user_id = 1 AND status = 'published'
ORDER BY created_at DESC;
```

重点先看几个字段：

| 字段 | 简单含义 |
|------|----------|
| `type` | 访问方式，越接近全表扫描通常越需要关注 |
| `possible_keys` | 可能使用的索引 |
| `key` | 实际选择的索引 |
| `rows` | 预估扫描行数 |
| `Extra` | 额外信息 |

不用一开始背所有执行计划字段，先学会用它确认 SQL 有没有机会走索引。

## 九、索引不是越多越好

索引有成本：

- 占用磁盘空间。
- 插入、更新、删除时要维护索引。
- 索引太多会增加优化器选择成本。

适合建索引的字段：

| 场景 | 示例 |
|------|------|
| 经常作为查询条件 | `WHERE email = ?` |
| 经常用于连接 | `posts.user_id` |
| 经常用于排序 | `ORDER BY created_at` |
| 需要唯一约束 | `email UNIQUE` |

不适合盲目建索引的字段：

- 很少查询的字段
- 频繁变化但很少过滤的字段
- 区分度很低的字段单独建索引，例如只有 `0` 和 `1` 的布尔字段

## 十、博客表常用索引

文章表可以考虑：

```sql
CREATE INDEX idx_posts_user_status_created
ON posts (user_id, status, created_at);

CREATE INDEX idx_posts_category_status_created
ON posts (category_id, status, created_at);
```

评论表可以考虑：

```sql
CREATE INDEX idx_comments_post_created
ON comments (post_id, created_at);
```

文章标签表已经有联合主键：

```sql
PRIMARY KEY (post_id, tag_id)
```

如果还经常从标签反查文章，可以补一个索引：

```sql
CREATE INDEX idx_post_tags_tag_post
ON post_tags (tag_id, post_id);
```

索引设计要围绕真实查询，不要脱离业务凭感觉添加。
