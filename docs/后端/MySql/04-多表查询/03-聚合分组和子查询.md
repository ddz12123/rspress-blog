# 聚合、分组和子查询

这一节学习统计类查询。

常见需求：

- 统计文章数量
- 统计每个分类下有多少文章
- 查询评论数最多的文章
- 查询浏览量高于平均值的文章

## 一、聚合函数

聚合函数会把多行数据计算成一个结果。

常见函数：

| 函数 | 含义 |
|------|------|
| `COUNT(*)` | 统计行数 |
| `SUM()` | 求和 |
| `AVG()` | 平均值 |
| `MAX()` | 最大值 |
| `MIN()` | 最小值 |

统计已发布文章数量：

```sql
SELECT COUNT(*) AS total
FROM posts
WHERE status = 'published';
```

统计总浏览量：

```sql
SELECT SUM(view_count) AS total_views
FROM posts
WHERE status = 'published';
```

统计平均浏览量：

```sql
SELECT AVG(view_count) AS avg_views
FROM posts
WHERE status = 'published';
```

## 二、COUNT(*) 和 COUNT(字段)

`COUNT(*)` 统计行数。

```sql
SELECT COUNT(*) AS total
FROM users;
```

`COUNT(age)` 只统计 `age` 不为 `NULL` 的行：

```sql
SELECT COUNT(age) AS users_with_age
FROM users;
```

如果只是统计有多少行，优先使用：

```sql
COUNT(*)
```

## 三、GROUP BY 分组

统计每个状态下的文章数量：

```sql
SELECT status, COUNT(*) AS post_count
FROM posts
GROUP BY status;
```

结果类似：

```text
status     | post_count
draft      | 1
published  | 3
archived   | 1
```

`GROUP BY status` 表示把相同状态的文章分到一组，再分别统计。

## 四、按分类统计文章数量

```sql
SELECT
    c.id,
    c.name AS category_name,
    COUNT(p.id) AS post_count
FROM categories AS c
LEFT JOIN posts AS p ON c.id = p.category_id
GROUP BY c.id, c.name
ORDER BY post_count DESC;
```

这里使用 `LEFT JOIN`，即使某个分类下没有文章，也能显示出来，数量为 `0`。

为什么用 `COUNT(p.id)`：

- `COUNT(*)` 会统计连接后的行。
- 对于没有文章的分类，`LEFT JOIN` 仍会产生一行，`COUNT(*)` 可能得到 `1`。
- `COUNT(p.id)` 只统计文章 ID 不为 `NULL` 的行。

## 五、HAVING 过滤分组结果

`WHERE` 是分组前过滤行。

`HAVING` 是分组后过滤统计结果。

查询文章数大于 1 的分类：

```sql
SELECT
    c.id,
    c.name AS category_name,
    COUNT(p.id) AS post_count
FROM categories AS c
LEFT JOIN posts AS p ON c.id = p.category_id
GROUP BY c.id, c.name
HAVING COUNT(p.id) > 1;
```

不要把聚合条件写到 `WHERE`：

```sql
-- 错误思路
WHERE COUNT(p.id) > 1
```

聚合函数条件应该放在 `HAVING`。

## 六、统计每篇文章评论数

```sql
SELECT
    p.id,
    p.title,
    COUNT(cm.id) AS comment_count
FROM posts AS p
LEFT JOIN comments AS cm ON p.id = cm.post_id
GROUP BY p.id, p.title
ORDER BY comment_count DESC, p.id DESC;
```

解释：

- `LEFT JOIN` 保证没有评论的文章也显示。
- `COUNT(cm.id)` 统计评论数量。
- `GROUP BY p.id, p.title` 按文章分组。

## 七、子查询

子查询就是 SQL 里面再写一个 SQL。

查询浏览量高于平均浏览量的文章：

```sql
SELECT id, title, view_count
FROM posts
WHERE view_count > (
    SELECT AVG(view_count)
    FROM posts
)
ORDER BY view_count DESC;
```

括号里的查询先算出平均浏览量，外层查询再拿它做条件。

## 八、IN 子查询

查询有评论的文章：

```sql
SELECT id, title
FROM posts
WHERE id IN (
    SELECT DISTINCT post_id
    FROM comments
);
```

含义：

1. 子查询先找出所有出现过评论的 `post_id`。
2. 外层查询再查这些文章。

这个需求也可以用 `JOIN` 写：

```sql
SELECT DISTINCT p.id, p.title
FROM posts AS p
INNER JOIN comments AS cm ON p.id = cm.post_id;
```

## 九、EXISTS 子查询

查询至少有一条评论的文章：

```sql
SELECT p.id, p.title
FROM posts AS p
WHERE EXISTS (
    SELECT 1
    FROM comments AS cm
    WHERE cm.post_id = p.id
);
```

`EXISTS` 关注的是子查询是否能找到结果。

对于“是否存在”这类需求，`EXISTS` 经常比把大量 ID 查出来再 `IN` 更合适。

## 十、查询写法选择

| 需求 | 常用写法 |
|------|----------|
| 查询关联字段 | `JOIN` |
| 统计数量、总和、平均值 | 聚合函数 |
| 按分类、状态统计 | `GROUP BY` |
| 过滤统计结果 | `HAVING` |
| 判断是否存在关联数据 | `EXISTS` |
| 用一个查询结果作为条件 | 子查询 |

复杂 SQL 不要一口气写完，建议分步骤：

1. 先查主表。
2. 再加 `JOIN`。
3. 再加 `WHERE`。
4. 再加 `GROUP BY`。
5. 最后加 `ORDER BY` 和 `LIMIT`。
