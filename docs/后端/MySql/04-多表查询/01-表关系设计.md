# 表关系设计

真实项目很少只有一张表。

例如博客系统至少会有：

- 用户表
- 分类表
- 文章表
- 评论表
- 标签表

这些表之间存在关系。

## 一、一对多关系

一个用户可以写多篇文章。

```text
users 1  ——  N posts
```

对应字段：

```text
posts.user_id -> users.id
```

也就是文章表里放一个 `user_id`，表示这篇文章属于哪个用户。

## 二、分类和文章也是一对多

一个分类下可以有多篇文章。

```text
categories 1  ——  N posts
```

对应字段：

```text
posts.category_id -> categories.id
```

## 三、多对多关系

一篇文章可以有多个标签，一个标签也可以属于多篇文章。

```text
posts N  ——  N tags
```

多对多不能直接用一个字段解决，通常需要中间表：

```text
posts 1 —— N post_tags N —— 1 tags
```

`post_tags` 表只负责保存文章和标签的对应关系。

## 四、创建分类表

```sql
CREATE TABLE categories (
    id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(50) NOT NULL,
    slug VARCHAR(80) NOT NULL,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT uk_categories_slug UNIQUE (slug)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

插入分类：

```sql
INSERT INTO categories (name, slug)
VALUES
    ('数据库', 'database'),
    ('后端开发', 'backend'),
    ('运维部署', 'devops');
```

## 五、创建文章表

这次文章表加上外键：

```sql
CREATE TABLE posts (
    id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT UNSIGNED NOT NULL,
    category_id BIGINT UNSIGNED NOT NULL,
    title VARCHAR(200) NOT NULL,
    content TEXT NOT NULL,
    status ENUM('draft', 'published', 'archived') NOT NULL DEFAULT 'draft',
    view_count INT UNSIGNED NOT NULL DEFAULT 0,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    CONSTRAINT fk_posts_user
        FOREIGN KEY (user_id) REFERENCES users(id),
    CONSTRAINT fk_posts_category
        FOREIGN KEY (category_id) REFERENCES categories(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

如果前面已经创建过 `posts` 表，本地练习时可以先删除旧表再创建：

```sql
DROP TABLE IF EXISTS posts;
```

> 删除表会删除表结构和数据。这里只适合教程练习环境。

## 六、创建评论表

一篇文章可以有多条评论：

```sql
CREATE TABLE comments (
    id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
    post_id BIGINT UNSIGNED NOT NULL,
    user_id BIGINT UNSIGNED NOT NULL,
    content VARCHAR(500) NOT NULL,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT fk_comments_post
        FOREIGN KEY (post_id) REFERENCES posts(id),
    CONSTRAINT fk_comments_user
        FOREIGN KEY (user_id) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

关系：

```text
comments.post_id -> posts.id
comments.user_id -> users.id
```

## 七、创建标签表和中间表

标签表：

```sql
CREATE TABLE tags (
    id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(50) NOT NULL,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT uk_tags_name UNIQUE (name)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

文章标签关系表：

```sql
CREATE TABLE post_tags (
    post_id BIGINT UNSIGNED NOT NULL,
    tag_id BIGINT UNSIGNED NOT NULL,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (post_id, tag_id),
    CONSTRAINT fk_post_tags_post
        FOREIGN KEY (post_id) REFERENCES posts(id),
    CONSTRAINT fk_post_tags_tag
        FOREIGN KEY (tag_id) REFERENCES tags(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

这里没有单独的 `id` 字段，而是使用：

```sql
PRIMARY KEY (post_id, tag_id)
```

表示同一篇文章和同一个标签只能绑定一次。

## 八、插入练习数据

先保证 `users` 里有数据。如果前面已经插入过同名用户，可以跳过这一步。

```sql
INSERT INTO users (username, email)
VALUES
    ('tom', 'tom@example.com'),
    ('jack', 'jack@example.com');
```

插入文章：

```sql
INSERT INTO posts (user_id, category_id, title, content, status, view_count)
VALUES
    (1, 1, 'MySQL 入门', '数据库基础内容', 'published', 120),
    (1, 1, '索引基础', '索引知识内容', 'published', 80),
    (2, 2, 'FastAPI 连接 MySQL', '后端连接数据库', 'draft', 10);
```

插入评论：

```sql
INSERT INTO comments (post_id, user_id, content)
VALUES
    (1, 2, '写得很清楚'),
    (1, 1, '继续补充一个例子'),
    (2, 2, '索引这部分很有用');
```

插入标签：

```sql
INSERT INTO tags (name)
VALUES ('MySQL'), ('SQL'), ('后端');
```

绑定文章和标签：

```sql
INSERT INTO post_tags (post_id, tag_id)
VALUES
    (1, 1),
    (1, 2),
    (2, 1),
    (2, 2),
    (3, 3);
```

## 九、表关系设计原则

| 原则 | 说明 |
|------|------|
| 一对多 | 在“多”的一方放外键 |
| 多对多 | 建中间表 |
| 外键字段类型 | 必须和被引用主键类型一致 |
| 中间表 | 可以用联合主键防止重复绑定 |
| 表名 | 尽量使用复数名，例如 `users`、`posts` |

理解表关系后，下一步就是用 `JOIN` 把多张表的数据查出来。
