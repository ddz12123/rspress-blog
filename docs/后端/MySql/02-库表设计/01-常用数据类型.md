# 常用数据类型

表字段必须选择数据类型。

数据类型决定了：

- 这个字段能存什么值
- 占用多少空间
- 能不能排序、计算、比较
- 数据库如何检查非法数据

## 一、数字类型

常见整数类型：

| 类型 | 占用 | 常见用途 |
|------|------|----------|
| `TINYINT` | 1 字节 | 年龄、状态、小范围数字 |
| `INT` | 4 字节 | 普通整数 |
| `BIGINT` | 8 字节 | 主键 ID、大数量统计 |

示例：

```sql
CREATE TABLE number_demo (
    id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
    age TINYINT UNSIGNED,
    view_count INT UNSIGNED NOT NULL DEFAULT 0
);
```

`UNSIGNED` 表示无符号，也就是不能存负数。

例如年龄不应该是负数，可以写：

```sql
age TINYINT UNSIGNED
```

## 二、金额不要用 FLOAT

金额应该使用 `DECIMAL`，不要用 `FLOAT` 或 `DOUBLE`。

```sql
price DECIMAL(10, 2) NOT NULL
```

含义：

| 写法 | 含义 |
|------|------|
| `10` | 总共最多 10 位数字 |
| `2` | 小数点后保留 2 位 |

例如 `DECIMAL(10, 2)` 可以保存：

```text
99999999.99
```

原因是 `FLOAT` 和 `DOUBLE` 是近似值，适合科学计算，不适合保存订单金额。

## 三、字符串类型

常见字符串类型：

| 类型 | 适合保存 |
|------|----------|
| `CHAR(n)` | 固定长度内容，例如固定 6 位验证码 |
| `VARCHAR(n)` | 长度变化的短文本，例如用户名、邮箱、标题 |
| `TEXT` | 长文本，例如文章正文、评论内容 |

示例：

```sql
CREATE TABLE string_demo (
    id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
    code CHAR(6) NOT NULL,
    username VARCHAR(50) NOT NULL,
    bio TEXT NULL
);
```

常用选择：

| 场景 | 推荐类型 |
|------|----------|
| 用户名 | `VARCHAR(50)` |
| 邮箱 | `VARCHAR(100)` |
| 手机号 | `VARCHAR(20)` |
| 文章标题 | `VARCHAR(200)` |
| 文章正文 | `TEXT` |

手机号不要用整数保存，因为手机号不是拿来做数学计算的，而且可能有国家区号、前导 0 等情况。

## 四、时间类型

常见时间类型：

| 类型 | 含义 |
|------|------|
| `DATE` | 日期，例如 `2026-06-07` |
| `TIME` | 时间，例如 `14:30:00` |
| `DATETIME` | 日期和时间，例如 `2026-06-07 14:30:00` |
| `TIMESTAMP` | 时间戳类型，会受时区设置影响 |

业务系统里常见写法：

```sql
created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
```

含义：

- `created_at`：插入数据时自动记录当前时间。
- `updated_at`：插入和更新数据时自动维护修改时间。

## 五、布尔值怎么存

MySQL 没有真正独立的布尔存储类型。

`BOOLEAN` / `BOOL` 在 MySQL 中本质上是 `TINYINT(1)` 的别名。

常见写法：

```sql
is_deleted TINYINT(1) NOT NULL DEFAULT 0
```

约定：

| 值 | 含义 |
|----|------|
| `0` | 否 |
| `1` | 是 |

## 六、枚举类型 ENUM

`ENUM` 表示字段只能从固定值里选一个。

```sql
status ENUM('draft', 'published', 'archived') NOT NULL DEFAULT 'draft'
```

适合值很稳定的场景：

- 文章状态：草稿、已发布、归档
- 用户状态：启用、禁用

如果状态经常变化，或者需要后台配置，建议单独建一张状态表，而不是频繁修改 `ENUM`。

## 七、JSON 类型

MySQL 支持 `JSON` 类型，适合保存结构不固定的扩展信息。

```sql
profile JSON NULL
```

插入示例：

```sql
INSERT INTO users (username, email, profile)
VALUES (
    'tom',
    'tom@example.com',
    JSON_OBJECT('city', 'Shanghai', 'level', 3)
);
```

查询 JSON 字段：

```sql
SELECT username, JSON_EXTRACT(profile, '$.city') AS city
FROM users;
```

注意：不要因为 JSON 灵活，就把本来应该设计成字段的数据全部塞进 JSON。经常用于筛选、排序、关联的数据，优先设计成普通字段。

## 八、博客文章表示例

下面是一张文章表的字段设计：

```sql
CREATE TABLE posts (
    id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT UNSIGNED NOT NULL,
    title VARCHAR(200) NOT NULL,
    content TEXT NOT NULL,
    status ENUM('draft', 'published', 'archived') NOT NULL DEFAULT 'draft',
    view_count INT UNSIGNED NOT NULL DEFAULT 0,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

字段说明：

| 字段 | 类型 | 原因 |
|------|------|------|
| `id` | `BIGINT UNSIGNED` | 适合做自增主键 |
| `user_id` | `BIGINT UNSIGNED` | 和用户表主键类型保持一致 |
| `title` | `VARCHAR(200)` | 标题长度有限 |
| `content` | `TEXT` | 正文可能较长 |
| `status` | `ENUM` | 状态值固定 |
| `view_count` | `INT UNSIGNED` | 浏览次数不应为负数 |
| `created_at` | `DATETIME` | 记录创建时间 |
| `updated_at` | `DATETIME` | 记录修改时间 |

## 九、选择类型的简单原则

| 场景 | 原则 |
|------|------|
| 主键 | 常用 `BIGINT UNSIGNED AUTO_INCREMENT` |
| 金额 | 用 `DECIMAL` |
| 手机号 | 用 `VARCHAR` |
| 中文文本 | 字符集用 `utf8mb4` |
| 是否字段 | 用 `TINYINT(1)`，约定 `0` 和 `1` |
| 创建时间 | 用 `DATETIME DEFAULT CURRENT_TIMESTAMP` |
| 更新时间 | 用 `DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP` |
