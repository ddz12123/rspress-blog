# 主键、自增和约束

表不只是存数据，还应该限制错误数据进入数据库。

这些限制就叫约束。

## 一、主键 PRIMARY KEY

主键用来唯一标识一行数据。

用户表里常见写法：

```sql
id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT
```

含义：

| 部分 | 含义 |
|------|------|
| `id` | 字段名 |
| `BIGINT UNSIGNED` | 无符号大整数 |
| `PRIMARY KEY` | 主键 |
| `AUTO_INCREMENT` | 自动递增 |

插入数据时不用手动写 `id`：

```sql
INSERT INTO users (username, email)
VALUES ('tom', 'tom@example.com');
```

MySQL 会自动生成下一个 `id`。

## 二、为什么需要主键

假设用户表没有主键：

| username | email |
|----------|-------|
| tom | tom@example.com |
| tom | tom@example.com |

要修改其中一行时，很难准确描述要修改哪一行。

有了主键：

| id | username | email |
|----|----------|-------|
| 1 | tom | tom@example.com |
| 2 | tom | tom@example.com |

就可以明确修改：

```sql
UPDATE users
SET username = 'tom01'
WHERE id = 1;
```

## 三、非空约束 NOT NULL

`NOT NULL` 表示字段不能为空。

```sql
username VARCHAR(50) NOT NULL
```

如果执行：

```sql
INSERT INTO users (email)
VALUES ('no-name@example.com');
```

会报错，因为 `username` 没有值。

哪些字段通常要 `NOT NULL`：

- 用户名
- 邮箱
- 密码哈希
- 文章标题
- 文章正文
- 创建时间

允许为空的字段通常是可选信息，例如头像、简介、生日。

## 四、唯一约束 UNIQUE

`UNIQUE` 表示字段值不能重复。

```sql
email VARCHAR(100) NOT NULL UNIQUE
```

如果已经有：

```sql
INSERT INTO users (username, email)
VALUES ('tom', 'tom@example.com');
```

再插入同样邮箱：

```sql
INSERT INTO users (username, email)
VALUES ('tom2', 'tom@example.com');
```

会报错。

唯一约束适合：

- 邮箱
- 手机号
- 用户名
- 订单号

## 五、默认值 DEFAULT

`DEFAULT` 表示插入数据时如果没有提供值，就使用默认值。

```sql
status ENUM('active', 'disabled') NOT NULL DEFAULT 'active'
```

插入：

```sql
INSERT INTO users (username, email)
VALUES ('jack', 'jack@example.com');
```

查询时 `status` 会是：

```text
active
```

## 六、检查约束 CHECK

MySQL 8.0.16 以后开始真正执行 `CHECK` 约束。

例如限制年龄范围：

```sql
CREATE TABLE check_demo (
    id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
    age TINYINT UNSIGNED,
    CONSTRAINT chk_age_range CHECK (age IS NULL OR age <= 120)
);
```

插入非法年龄：

```sql
INSERT INTO check_demo (age)
VALUES (200);
```

会因为不满足检查约束而失败。

实际项目里，数据库约束和后端参数校验应该一起使用：

- 后端校验负责给用户友好提示。
- 数据库约束负责兜底，防止脏数据写入。

## 七、外键约束 FOREIGN KEY

外键用来保证两个表之间的关联是有效的。

例如文章属于某个用户：

```sql
CREATE TABLE posts (
    id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT UNSIGNED NOT NULL,
    title VARCHAR(200) NOT NULL,
    content TEXT NOT NULL,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT fk_posts_user
        FOREIGN KEY (user_id) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

这表示：

```text
posts.user_id 必须引用 users.id 中已经存在的值
```

如果用户 `999` 不存在：

```sql
INSERT INTO posts (user_id, title, content)
VALUES (999, '错误文章', '这个用户不存在');
```

会插入失败。

## 八、外键的删除行为

创建外键时可以指定删除用户后文章怎么处理。

常见选择：

| 写法 | 含义 |
|------|------|
| `ON DELETE RESTRICT` | 有关联数据时禁止删除，默认接近这种思路 |
| `ON DELETE CASCADE` | 删除用户时自动删除文章 |
| `ON DELETE SET NULL` | 删除用户时把文章的 `user_id` 设为 `NULL` |

示例：

```sql
CONSTRAINT fk_posts_user
    FOREIGN KEY (user_id) REFERENCES users(id)
    ON DELETE RESTRICT
    ON UPDATE CASCADE
```

建议先使用限制删除的思路，避免误删用户时把文章也一起删掉。

## 九、完整用户表示例

```sql
CREATE TABLE users (
    id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50) NOT NULL,
    email VARCHAR(100) NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    age TINYINT UNSIGNED NULL,
    status ENUM('active', 'disabled') NOT NULL DEFAULT 'active',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    CONSTRAINT uk_users_username UNIQUE (username),
    CONSTRAINT uk_users_email UNIQUE (email),
    CONSTRAINT chk_users_age CHECK (age IS NULL OR age <= 120)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

这里给约束起了名字：

| 约束名 | 含义 |
|--------|------|
| `uk_users_username` | 用户名唯一 |
| `uk_users_email` | 邮箱唯一 |
| `chk_users_age` | 年龄检查 |

给约束起清晰名字，后面排查错误和修改结构会更方便。

## 十、约束设计原则

| 原则 | 说明 |
|------|------|
| 每张业务表都要有主键 | 后续更新、删除、关联都依赖它 |
| 关键字段尽量 `NOT NULL` | 避免出现不完整数据 |
| 业务唯一字段加 `UNIQUE` | 例如邮箱、订单号 |
| 外键字段类型要一致 | `posts.user_id` 和 `users.id` 类型应该一致 |
| 不要只依赖后端校验 | 数据库约束是最后一道防线 |
